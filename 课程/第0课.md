### 1. PostgreSQL 18

**装哪个版本：** PostgreSQL **18**（当前稳定版 18.6）。

**为什么不装更早的：** 13 及以下已经停止支持（2025-11 结束）。教程和实测会对不上。

**装在哪：** 三条路选一条，第 1 天会上手实操。第 0 课只需要"确认你打算走哪条"：

| 走哪条 | 是什么 | 什么时候选 |
| --- | --- | --- |
| ZIP 免安装版 | 解压一个文件夹，手动 `initdb` | **默认选这条**，不需要管理员权限 |
| Docker Desktop | 镜像里跑一个 Linux 版 PostgreSQL | 第 15 周会正式学，第 0 课可以先跳过 |
| EDB 官方 Installer | 装成一个 Windows 服务 | 不想碰命令行时 |

**验证必须带一句"看到这个就算成功"。** 装完跑这一条：

```
psql -U postgres -h 127.0.0.1 -c "SELECT version();"
```

**该看到这样的输出：**

```
                                                 version
----------------------------------------------------------------------------------------------------------
 PostgreSQL 18.6 on x86_64-windows, compiled by msvc-19.44.35211, 64-bit
(1 row)
```

**看到什么算不对：**

| 屏幕上出现 | 说明什么 |
| --- | --- |
| `command not found` / `不是内部或外部命令` | `psql` 没进 `PATH`，要用完整路径 |
| `could not connect to server` | 服务没启动 |
| `password authentication failed` | 用户名或密码不对 |
| 版本号不是 18 | 装错版本了，或者旧版本还在 `PATH` 里 |

### 2. 仓库

**还没有远程仓库。这门课开始时会现建一个，建完把地址填在这里：**

```
远程仓库地址：____________________（开始上课时填）
```

**第一次要做的三件事：**

```bash
# 把这个学习项目初始化成一个 git 仓库
git init

# 把当前目录所有文件加入待提交清单
git add .

# 提交，留下第一个存档点
git commit -m "第0课：初始化 SQL 学习项目"

# 关联远程仓库（地址等建好仓库后替换）
git remote add origin <远程仓库地址>

# 推上去，并记住这个分支名
git push -u origin main
```

**提交信息要说清加了什么。** 不要写 `update`、`fix`、`修改一下` —— 三个月后看不懂。

### 3. 忽略清单

**哪些文件绝不进仓库：**

```gitignore
# 数据目录 —— 这是整个数据库的全部内容，体积大、且不该进版本库
pgdata/

# PostgreSQL 二进制 —— 几百 MB，每台机器自己装
pgsql/

# 日志文件
*.log

# Python 虚拟环境（第 3 周开始用）
.venv/

# Python 编译缓存
__pycache__/
```

**为什么数据目录和二进制不进仓库：** 它们属于"每台机器自己装一份"，不属于"你的代码"。

> ⚠️ 和直觉相反：**本例不需要 `.env`、也不管密码和密钥。**
> 这是学习项目，数据库跑在本机，没有真实凭据。
> 但第 12 周接上真实项目后，这条要重新加回来 —— 那时才真有东西不能提交。

### 4. 生词本

**建一个空文件，叫 `生词本.md`。**

**它不是知识笔记，是一本代码词典。** 读代码碰到不认识的词，翻开查一下。

**格式是每行三样，第三样不超过一行：**

| 代码里的词 | 中文短名 | 一句话 |
| --- | --- | --- |
| `psql` | 命令行客户端 | 在终端里连数据库、敲 SQL 的那个程序 |
| `initdb` | 初始化数据目录 | 把一片空文件夹变成一个能用的数据库 |
| `pg_ctl` | 服务控制 | 启动、停止、重启数据库的那个命令 |
| `git` | 版本控制 | 给文件存历史存档的工具 |
| `commit` | 提交 | 拍一张当前状态的快照，存进历史 |
| `push` | 推送 | 把本地的快照传到远程仓库 |
| `pull` | 拉取 | 把远程的快照取回本地 |

**"一句话"里不写"怎么用""什么时候用"** —— 那是课的内容。

**第 0 课当场就记这几条，不要留到课后。** 空文件谁都会建，当场做一次，这个习惯才立得住。

### 5. 两台机器

**这是这门课最容易出事的地方，所以要写在最前面：**

> **同一个项目，两台电脑轮流做。**

**四条规矩：**

| 什么时候 | 做什么 |
| --- | --- |
| 每节课结束 | 就提交、就推送 —— **不留"以后再提交"** |
| 换机器**之前** | `push` |
| 换机器**之后** | 先 `pull` |
| 任何时候 | 数据目录和二进制不进仓库 |

### 最后一条不是漏洞，是设计

**每台机器可以有自己的 PostgreSQL 安装路径、自己的数据目录、自己的端口。** 这本来就是要的。

**但它带来一个风险：两台机器的环境会悄悄不一致，然后"在我这能跑"就出现了。**

**所以第 0 课还要建一份"环境差异记录"** —— 哪台机器、哪个值、为什么不一样。

**先开个头，把已知的填上：**

| 机器 | PostgreSQL 版本 | 安装路径 | 数据目录 | 端口 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 机器 A |  |  |  |  |  |
| 机器 B |  |  |  |  |  |

**这份记录的用处：** 下次在某台机器上报错而另一台正常时，**第一件事就是翻它。**
