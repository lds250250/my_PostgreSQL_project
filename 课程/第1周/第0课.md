### 1. PostgreSQL 18

**装哪个版本：** PostgreSQL **18**（当前稳定版 18.6）。

**为什么不装更早的：** 13 及以下已经停止支持（2025-11 结束）。教程和实测会对不上。

**装在哪：** 三条路选一条。**实际选的是 ZIP 免安装版**：

| 走哪条 | 是什么 | 结果 |
| --- | --- | --- |
| **ZIP 免安装版** | 解压一个文件夹，手动 `initdb` | ✅ **选定了**。装在 `G:\Project\PostgreSQL_pocket\`，不在项目文件夹里 |
| Docker Desktop | 镜像里跑一个 Linux 版 PostgreSQL | 第 15 周会正式学（pgvector 靠它） |
| EDB 官方 Installer | 装成一个 Windows 服务 | 没选 |

> **为什么程序和数据放在项目文件夹外面**：它们各几百 MB，是"工具和数据库本身"，不是"你的笔记"。
> 分开放之后，`git` 永远不会误把它们提交上去。

**验证必须带一句"看到这个就算成功"。** 装完跑这一条：

```powershell
$PG = "G:\Project\PostgreSQL_pocket\pgsql\bin"
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "SELECT version();"
```

**该看到这样的输出：**

```
                                                 version
----------------------------------------------------------------------------------------------------------
 PostgreSQL 18.6 on x86_64-windows, compiled by msvc-19.44.35228, 64-bit
(1 行记录)
```

> `(1 行记录)` 不是错误 —— 中文 Windows 环境下 `psql` 会把提示信息本地化，它等于英文的 `(1 row)`。

**看到什么算不对：**

| 屏幕上出现 | 说明什么 |
| --- | --- |
| `不是内部或外部命令` | `psql` 没进 `PATH`，要用完整路径或先定义 `$PG` |
| `Connection refused` | 服务没启动 —— 先去 Day 1 学 `pg_ctl start` |
| `password authentication failed` | 用户名或密码不对 |
| 版本号不是 18 | 装错版本了，或者旧版本还在 `PATH` 里 |

### 2. 仓库

**远程仓库地址（已填）：**

```
git@github.com:lds250250/my_PostgreSQL_project.git
```

**第一次要做的几件事（已做完）：**

```bash
# 把这个学习项目初始化成一个 git 仓库
git init

# 关联远程仓库
git remote add origin git@github.com:lds250250/my_PostgreSQL_project.git

# 把当前目录所有文件加入待提交清单
git add .

# 提交，留下第一个存档点
git commit -m "Day 0：初始化 SQL 学习项目"

# 推上去，并记住这个分支名
git push -u origin main
```

**提交信息要说清加了什么。** 不要写 `update`、`fix`、`修改一下` —— 三个月后看不懂。

> ⚠️ **这次踩到的坑：`git remote add` 的地址写重了。**
> 写成了 `git@github.com:git@github.com:lds250250/...`（`git@github.com:` 出现了两次），推不上去。
> **正确的 SSH 地址格式只有一种**：`git@github.com:<用户名>/<仓库名>.git`
> 写错了用 `git remote set-url origin <正确地址>` 改，不用删了重加。

**验证仓库配好了：**

```bash
git remote -v
```

应该打印两行（fetch 和 push），地址都对。

### 3. 忽略清单

**哪些文件绝不进仓库 —— 实际用的 `.gitignore`：**

```gitignore
# PostgreSQL 数据目录和程序都不在仓库里（它们放在 G:\Project\PostgreSQL_pocket\）
# 下面这些是"万一哪天跑到项目文件夹里"的兜底规则。

# 数据库数据目录
pgdata/
pgsql/

# 日志
*.log

# Python 虚拟环境和缓存（Day 19 起会用）
.venv/
venv/
__pycache__/
*.pyc
```

**为什么数据目录和二进制不进仓库：** 它们属于"每台机器自己装一份"，不属于"你的代码"。

> ⚠️ 和直觉相反：**本例不需要 `.env`、也不管密码和密钥。**
> 这是学习项目，数据库跑在本机，没有真实凭据。
> 但第 12 周接上真实项目后，这条要重新加回来 —— 那时才真有东西不能提交。
>
> **实际做法**：`.gitignore` 里把 `.env` 那两行**注释掉**，并在旁边写清"为什么现在不要、什么时候加回来"。
> 这样三个月后你看得懂，而不是对着一个空规则发愣。

**还有一个实情**：因为 `pgsql\` 和 `pgdata\` 都在项目文件夹外面，`git` 本来就看不见它们 ——
**这份 `.gitignore` 现在是兜底的**，真正起作用要等 Day 22 产出 `load_notes.py` 之后。

### 4. 生词本

**建一个文件 —— 但实际做下来发现一本不够，按领域分册了。**

原因：一本混装 PostgreSQL、PowerShell、SQL 三类的词，查一个词要来回翻。

**实际结构：**

```
速查\生词本\
├── 目录.md          <- 总目录，说明分册规则
├── PostgreSQL.md    <- psql / initdb / pg_ctl / 连接参数 / 元命令 / 配置
├── PowerShell.md    <- $PG / $LASTEXITCODE / Get-Content 等 cmdlet
├── SQL.md           <- SQL 语言本身的词
├── Python.md        <- Day 19 建（uv / psycopg）
└── Docker.md        <- 第 15 周建
```

**它不是知识笔记，是一本代码词典。** 读代码碰到不认识的词，翻开查一下。

**格式是每行三样，第三样不超过一行：**

| 代码里的词 | 中文短名 | 一句话 |
| --- | --- | --- |
| `psql` | 命令行客户端 | 在终端里连数据库、敲 SQL 的那个程序 |
| `initdb` | 初始化数据目录 | 把一片空文件夹变成一个能用的数据库 |
| `pg_ctl` | 服务控制 | 启动、停止、重启数据库的那个命令 |
| `git` | 版本控制 | 给文件存历史存档的工具 |
| `commit` | 提交 | 拍一张当前状态的快照，存进历史 |
| `push` | 推送 | 把本地的快照传到远程仓库 |
| `pull` | 拉取 | 把远程的快照取回本地 |

**"一句话"里不写"怎么用""什么时候用"** —— 那是课的内容。

**第 0 课当场就记这几条，不要留到课后。** 空文件谁都会建，当场做一次，这个习惯才立得住。

> **实际记了多少**：Day 0 + Day 1 合起来已经记了 **42 条**（分在 PostgreSQL 29 条、PowerShell 24 条、SQL 2 条里，有些词两边都出现）。

### 5. 两台机器

**这是这门课最容易出事的地方，所以要写在最前面：**

> **同一个项目，两台电脑轮流做。**

**四条规矩：**

| 什么时候 | 做什么 |
| --- | --- |
| 每节课结束 | 就提交、就推送 —— **不留"以后再提交"** |
| 换机器**之前** | `push` |
| 换机器**之后** | 先 `pull` |
| 任何时候 | 数据目录和二进制不进仓库 |

### 最后一条不是漏洞，是设计

**每台机器可以有自己的 PostgreSQL 安装路径、自己的数据目录、自己的端口。** 这本来就是要的。

**但它带来一个风险：两台机器的环境会悄悄不一致，然后"在我这能跑"就出现了。**

**所以第 0 课还要建一份"环境差异记录"** —— 哪台机器、哪个值、为什么不一样。

**机器 A（公司电脑，`G:` 盘）和机器 B（家里电脑，`C:` 盘）：**

| 机器 | PostgreSQL 版本 | 程序目录 | 数据目录 | 端口 |
| --- | --- | --- | --- | --- |
| 机器 A（公司） | 18.6 | `G:\Project\PostgreSQL_pocket\pgsql` | `G:\Project\PostgreSQL_pocket\pgdata` | 5432 |
| 机器 B（家里） | 18.6 | `C:\Users\Admin\Documents\Project\PostgreSQL_pocket\pgsql` | `C:\Users\Admin\Documents\Project\PostgreSQL_pocket\pgdata` | 5432 |

**这份记录的用处：** 下次在某台机器上报错而另一台正常时，**第一件事就是翻它。**

**两台唯一的不一样是"盘符 + 路径前缀"** ——
公司是 `G:`，家里是 `C:`。**其余（版本、端口、目录结构）完全一致。**
所以命令本身通用，**只有 A 段那四个变量要换**。

> **实操时去 `速查/PostgreSQL速查.md` 的 A 段**：那里有两块变量，抄对应那块，整块粘贴。
> **别背路径** —— 背错了要去查半天。

**换机器时，除了路径，还有一件事容易忘**：
在家写的 `.sql` 脚本、笔记，走之前 `push`、到了先 `pull`（见上面四条规矩）。

**还有一处"和教程不一样"**：程序和数据都放在 `PostgreSQL_pocket`，不在项目文件夹 `my_PostgreSQL_project` 里。
两台都是这个放法 —— **这是好的，别改**。
