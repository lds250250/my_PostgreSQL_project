**本课的点**

- **难点**：**两个帮助都不来自服务器** —— 但 `psql` 不连上就不给你看

**今天唯一要形成的模型：**

> **`psql` 自带一本手册。`\?` 是元命令的手册，`\h` 是 SQL 的手册。
> 两者都躺在你的电脑上 —— 但 `psql` 要先连上服务器，才肯翻给你看。**

## 一、今天解决什么问题

**你有没有过这种情况：想敲一个命令，但忘了它到底叫什么、参数怎么写？**

按之前的做法，你得：切出窗口 → 打开浏览器 → 搜 → 在一堆过时博客里找 → 再切回来。

**更难受的是**：你在 `psql` 里敲了半天的长 SQL，发现少写了一个词，
想改 —— **只能从头重敲一遍**。

**今天学的就是这个 —— 它叫自省命令（`\?` 和 `\h`），外加三个提高效率的工具。**

**一句话说：`\?` 列出所有反斜杠命令，`\h 关键词` 给出那条 SQL 的语法。手册就在你手边。**

**你可能原来是这样理解的：**

> 学数据库就是背命令 —— 背不下来就查文档。文档在官网上。

**这个理解错在哪？** 官方文档确实权威，但**日常 90% 的问题不需要出 `psql`**。
而且它让你养成了一个坏习惯：**遇到不会的，第一反应是去搜，而不是先在工具里找。**

**学完你能做出什么：** 在 `psql` 里敲 `\?` 找到你要的元命令，敲 `\h 关键词` 看到 SQL 语法，
不用离开终端。

### 1. 今天的最小工具箱

| 命令 | 干什么 | 谁处理 |
|---|---|---|
| `\?` | 列出**所有元命令**，并说明每个干什么 | `psql` |
| `\h 关键词` | 给出**那条 SQL 的语法** | `psql` |
| `\h` | 不带参数，列出所有有文档的 SQL 命令 | `psql` |
| `\e` | 用**外部编辑器**写多行 SQL | `psql` → 调用编辑器 |

### 2. 实验 A：正常路径 —— 三样一起试

**连进去：**

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1
```

**第一样：查元命令手册**

```sql
\?
```

**应该看到一整屏分类列表**，大致是这种格式（后面还有好几类）：

```
General
  \copyright             show PostgreSQL usage and distribution terms
  \crosstabview [COLUMNS] execute query and display results in crosstab
  ...
Informational
  \d[S+]                 list tables, views, and sequences
  \dt[S+] [PATTERN]      list tables
  \du[S+] [PATTERN]      list roles
  ...
```

**看到 `[S+]` 这种方括号了吗？** 那是**可选参数**的写法 ——
`\dt` 后面能跟东西，`S` 和 `+` 是两个可选的开关。**以后看到任何方括号，都读作"可选"。**

**第二样：查 SQL 语法**

```sql
\h SELECT

\h INSERT
```

**应该看到这段 SQL 的完整语法结构**，格式是：

```
Command:     SELECT
Description: retrieve rows from a table or view
Syntax:
SELECT [ ALL | DISTINCT [ ON ( expression [, ...] ) ] ]
    [ * | expression [ [ AS ] output_name ] [, ...] ]
    ...
```

**第三样：两个开关**

```sql
-- 打开计时
\timing

-- 随便跑一条
SELECT 1;

-- 现在换一个明显更慢的：算一百万个数的和
SELECT count(*) FROM generate_series(1, 1000000);

-- 关掉计时
\timing
```

### 这里应该出现一个让我"咦"的现象

**看 `\timing` 那两行输出：`SELECT 1;` 很快就出来了，
而 `generate_series(1, 1000000)` 那一条 —— 会看到一个具体的时间数字。**

**这个数字是"这台机器此刻"的数字，不是常量。**
记住这一点 —— 它是 Day 9 那个百万行实验的基础。

**还有：`\timing` 打开后，它会在每条 SQL 后面都加一行。这就是"开关式命令"的行为。**

### 3. 实验 B / C / D：三个错误，各有目的

| 实验 | 错误类型 | 它想打破的理解 |
|---|---|---|
| B | 用户错误（`\h` 查一个不存在的词） | "帮助文档什么都能查" |
| C | 环境错误（`\i` 指向一个不存在的文件） | "脚本跑不了是 SQL 写错了" |
| D | **边界错误（不连服务器时 `\h` 能不能用）** | "`\h` 是本地的，所以不需要连服务器" |

**B —— 查一个不存在的词：**

```sql
\h 不存在的词
```

**应该看到：**

```
No help available for "不存在的词".
Try \h with no arguments to see available help.
```

**注意它的语气**：不是报错（没有 `ERROR:`），是**礼貌地说"没这个"**，并**告诉你下一步怎么办**。

**C —— `\i` 指向一个不存在的文件：**

```sql
\i G:\不存在的目录\nope.sql
```

**这个错误是另一个性质的** —— `psql` 要去读文件，读不到，**和服务器一点关系都没有**。

**D —— 这个实验要在 `psql` 外面做。** 先退出（`\q`），停掉服务，再试帮助：

```powershell
# 退出 psql 后，先停服务
& "$PG\pg_ctl.exe" -D $DATA stop

# 现在试 \h —— 注意它连不上
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "\h SELECT"
```

**结果见第三节 —— 它是今天最反常识的一条。**

## 三、观察现象和解释

### 先自己想一下：`\h` 的内容是本地的，那没连上服务器能用吗？

**答案是 —— 不能。**

**实际验证结果**（服务停着时执行）：

```
psql: error: connection to server at "127.0.0.1", port 5432 failed: Connection refused (0x0000274D/10061)
        Is the server running on that host and accepting TCP/IP connections?
```

**`psql` 压根没给你看 `\h` 的内容，它先卡在"连不上"。**

**这是今天最值钱的一条：**

> **`\?` 和 `\h` 的内容确实存在你的电脑上 —— 但 `psql` 是个"必须先连上才干活"的工具。
> 它不先确认连接，连自己的手册都不翻给你看。**

**为什么这么设计？** 因为 `psql` 的基本假设是"你在操作一个数据库"。
它启动时就把连接建立好，后面所有命令都在这个连接的上下文里跑。
**帮助命令虽然不需要服务器数据，但走了同一条"先连接"的路。**

### 常见误解 → 更正

| 大多数人会以为 | 其实是 |
|---|---|
| "`\h` 是本地的，服务没开也能用" | **不能。** `psql` 不连上就不给任何输出 |
| "帮助内容来自服务器" | **不是。** 它来自你装的 `psql` 这份程序，跟你连哪个库无关 |
| "`\h` 什么词都能查" | 只能查 **SQL 命令关键字**（`SELECT`、`INSERT`…）。函数名、元命令查不到 |
| "查不到会报错" | 是**礼貌提示**：`No help available for ...` + 告诉你下一步 |
| "脚本跑不了，一定是 SQL 写错了" | 先看**文件在不在** —— `\i` 读不到文件，和服务器无关 |
| "命令只能一行一行敲" | `\e` 开编辑器写多行；`\i` 直接跑整个脚本 |
| "`\e` 是 `psql` 自己实现的编辑器" | **不是**，它去调用**外部程序**（由 `EDITOR` 环境变量决定） |

### 错误 B 的输出，值得单独看

```
No help available for "不存在的词".
Try \h with no arguments to see available help.
```

**注意三件事：**

1. **没有 `ERROR:`** —— 它不是错误，是"没找到"。**又是一条"看外形判断谁在说话"的证据。**
2. **它告诉你下一步** —— `Try \h with no arguments`。好的工具都会这样。
3. **它没建议你去搜官网** —— 它先说"我这里就有手册，你去翻"。

### `\h` 和 `\?` 的分工，是今天最实用的一张表

| 你想知道 | 敲什么 |
|---|---|
| 某个**反斜杠命令**干什么 | `\?`，然后在列表里找 |
| 某条 **SQL 语句**怎么写 | `\h 关键字`，比如 `\h INSERT` |
| 有哪些 SQL 语句有文档 | `\h`（不带参数） |
| 报错是什么意思 | 看报错的 `DETAIL` / `HINT`（Day 3 学的） |

## 四、解释原理

### （一）它怎么工作

| 命令 | 谁处理 | 出错时谁报错 | 怎么反推 |
|---|---|---|---|
| `\?` / `\h` | `psql`（内容在本地） | `psql`（`No help available`） | 没找到 ≠ 错误。它没查服务器 |
| `\i 文件` | `psql` 读文件 → 内容发给服务器 | **两边都可能** | 文件读不到 → `psql`；SQL 有错 → 服务器 |
| `\e` | `psql` **调用外部编辑器** | 编辑器或 `psql` | 提示打不开编辑器 = 环境变量问题 |
| `\! 命令` | `psql` **调用操作系统** | 操作系统 | 报错是 Windows 的语气，不是数据库的 |
| `\timing` | `psql` 自己计时 | —— | 显示的是**你这台机器**的数字 |
| `\x` | `psql` 改显示格式 | —— | 只影响显示，不影响数据 |

**注意 `\e` 和 `\!` 那两行**：`psql` 在这里**不是自己在干活，是去指挥别的程序**。
所以它们的报错长得跟数据库报错完全不同 —— **又是一次"看外形判断谁在说话"**。

**`\i` 是最值得注意的一个**：它横跨两层 ——
`psql` 先读文件（本地操作），再把内容发给服务器（网络操作）。
**所以它的报错有两种来源，这是本课第三次遇到"一条命令跨两层"。**

### （二）为什么这样设计

```
存在的问题
  用数据库时，要频繁确认两件事：这个命令怎么拼？这个语法怎么写？
        ↓
为什么"查官网"不够用
  · 要切窗口、搜、分辨过时内容 —— 打断思路
  · 官网文档对应最新版；你装的可能是别的版本，语法有差别
  · 现场排查时最缺的就是"别让我离开终端"
        ↓
这个设计解决了什么
  · \? 和 \h 把手册放进工具里 —— 版本和你装的这一份严格对应
  · \e 让长 SQL 可编辑，不用重敲
  · \i 让脚本可复用 —— 一次写好，以后一条命令跑完
  · \timing 让"快慢"从感觉变成数字
        ↓
它带来了什么新代价
  · \h 只覆盖 SQL 命令关键字，函数、扩展、元命令它不管
  · \e 依赖外部程序，可能打不开
  · \i 把"文件读不到"和"SQL 写错"两种错误混在一条命令里
  · 帮助是英文的，且是浓缩格式，第一次看要适应
```

### （三）好处和代价

| 用自省命令，好处是什么 | 代价是什么 |
|---|---|
| 不离开终端就能查语法和命令 | 只覆盖 SQL 关键字，不覆盖函数/扩展 |
| 内容和你装的版本严格对应 | 是英文浓缩格式，要学一会儿才看得顺 |
| `\i` 让脚本可复用、可提交进 git | 一条命令混了两层错误来源，排查要分步 |
| `\timing` 把性能变成数字 | 数字随机器变，**不能直接和别人对比** |

**什么条件下该换别的做法：**

- 要查**函数**（`coalesce`、`date_trunc`）→ `\h` 帮不上，得看官方文档的函数章节
- 要查**扩展**（`pgvector`、`pg_trgm`）→ 更得看各自的文档
- 要**系统学**一块知识 → 官方文档比 `\h` 合适；`\h` 是用来"想起来一半"时补全的

## 五、提炼判断规律

**判断规则（要有顺序）：**

```
在 psql 里"卡住"了
  ↓
第一步：是不是忘了元命令叫什么？
        是 → 敲 \? ，在分类列表里找
  ↓
第二步：是不是忘了某条 SQL 的语法？
        是 → 敲 \h 关键词
        查不到 → 它可能不是 SQL 关键字（是函数或扩展），去官网
  ↓
第三步：要写很长的 SQL？
        → \e 开编辑器（别在终端里敲）
  ↓
第四步：这段 SQL 要反复用？
        → 存成 .sql 文件，用 \i 跑
  ↓
第五步：想知道快慢？
        → \timing 打开，跑完看数字 —— 但记住数字是这台机器的
```

**支撑它的对照表：**

| 现象 | 谁报的 | 到哪一层 | 怎么处理 |
|---|---|---|---|
| `No help available for "X"` | `psql` | 本地手册 | **不是错误**。换个词，或 `\h` 不带参数看清单 |
| `could not open file "X"` | `psql` | 本地文件系统 | 检查路径；**和服务器无关** |
| `ERROR: syntax error at or near ...` | 服务器 | 服务器 | SQL 写错了 —— 用 `\h` 对照语法 |
| 提示打不开编辑器 | `psql` / 系统 | 本地环境 | 设 `EDITOR` 环境变量 |
| `\timing` 出来的数字很大 | —— | 你的机器 | 先别下结论，看是不是机器慢 |

**边界：** 这套方法有一个明确的天花板 ——
**`\h` 只覆盖 SQL 命令关键字。** 想问"`date_trunc` 怎么用"，它答不了。
**知道天花板在哪，比知道它有用更重要** —— 否则你会浪费时间去 `\h` 一个函数名。
