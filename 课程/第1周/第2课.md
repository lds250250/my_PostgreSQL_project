**本课的点**

- **难点**：区分**谁在处理你的命令**（`psql` 客户端 / PostgreSQL 服务器）

**今天唯一要形成的模型：**

> **一条命令从你到数据库要经过两个程序 —— `psql` 和服务器。
> 报错的"外形"告诉你是哪一步出的问题。**

## 一、今天解决什么问题

**你有没有过这种情况：敲完一条 SQL，想接着敲下一条，结果程序已经退出了？**

到 Day 1 为止，我们每次都写 `-c "SELECT version();"` —— 执行完那一句，`psql` 就走了。
想再问一句，得重新连一次。

真实干活不是这样的。你会连着敲十几条，中间还要看"这库里有什么表""这表有哪些列"。

**今天学的就是这个 —— 它叫元命令（meta-command），在 `psql` 里以反斜杠 `\` 开头。**

**一句话说：`\l` 就是"list 一下有哪些数据库"，`\d` 就是"describe 一下这张表长什么样"。**

**你可能原来是这样理解的：**

> 每次要用数据库，都得写一条完整的命令，执行完就结束 —— 数据库就是"一问一答"。

**这个理解错在哪？** 它让你每次只能问一句话。**而且它掩盖了一件更重要的事：
你敲的命令，有的一直没离开你的电脑。**

**学完你能做出什么：** 进到 `psql` 里不出来，连续敲十几条命令，中间随时查库、查表、查结构。

| "没有服务器进程"、退出码 3 | **保持停机**，直接做实验 A |

### 1. 今天的最小工具箱

| 命令 | 联想 | 干什么 | 谁处理 |
|---|---|---|---|
| `\l` | **l**ist | 列出所有**数据库** | `psql` |

### 2. 实验 A：正常路径

**在服务确定停机的情况下，敲这一条：**

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "SELECT 1;"
```

**然后启动服务，再敲一遍同样的命令：**

```powershell
# 启动
& "$PG\pg_ctl.exe" -D $DATA -l $LOG start

# 再试一次
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "SELECT 1;"
```

**成功时：**

```
 ?column?
----------
        1
(1 行记录)
```

> `?column?` 是因为这句 SQL 没给结果列起名，不是错误。

**然后进交互界面：**

```powershell
# 和以前唯一的区别：结尾没有 -c
& "$PG\psql.exe" -U postgres -h 127.0.0.1
```

**进去后提示符变成 `postgres=#`，在里面依次敲：**

```sql
\l

\dt

\c postgres

\q
```

### 这里应该出现一个让我"咦"的现象

**停机和开机，你敲的是同一条命令，但结果是两种完全不同的报错。**

停机时：

```
psql: 错误: 连接到"127.0.0.1"上的服务器，端口5432失败：Connection refused (0x0000274D/10061)
        Is the server running on that host and accepting TCP/IP connections?
```

**这条报错里，有一个字是数据库说的吗？** 没有。**它全是 `psql` 自己说的。**

**记住这个"外形"—— 它是今天唯一的判断依据。**

### 3. 实验 B / C / D：三个错误，各有目的

| 实验 | 错误类型 | 它想打破的理解 |
|---|---|---|
| B | **参数错误（主机写错）** | "地址写错"和"服务没启动"是两回事 —— **其实报错一模一样** |
| C | **参数错误（端口写错）** | 同上，也是"路不通" |
| D | 用户错误（元命令拼错） | `psql` 报错和服务器报错，**外形不一样** |

**先确认服务是开着的**，然后：

```powershell
# B：主机写错（一个不存在的 IP）—— 注意它可能卡几秒
& "$PG\psql.exe" -U postgres -h 1.2.3.4 -c "SELECT 1;"

# C：端口写错
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -p 9999 -c "SELECT 1;"

# D：元命令拼错（要在 psql 里面敲）
& "$PG\psql.exe" -U postgres -h 127.0.0.1
```

进去之后：

```sql
\dtx
```

**B 会卡几秒才报错** —— 因为它是真的往网络上发请求，在等一个不存在的地址回应。
**这个"卡顿"本身就是线索。**

## 三、观察现象和解释

### 先自己想一下：`Connection refused` 说明连到服务器了吗？

**答案是 —— 没有。**

`Connection refused` 的含义是：**我发出连接请求了，但那个端口上没有程序在听。**

**这一条最重要：**

> **`Connection refused` 是"客户端到服务器的路不通"，不是"服务器拒绝了你"。**
> 车根本没开到，谈不上"对方拒绝"。

### 常见误解 → 更正

| 大多数人会以为 | 其实是 |
|---|---|
| "`Connection refused` 是服务器拒绝了我" | **服务器根本不在场**，是路不通 |
| "服务没启动"和"端口写错"是两回事 | 从客户端看是**同一件事**：那个地址没回应 |
| "`Is the server running...?` 是原因" | 那是**提示（猜测）**，不是原因 |
| "元命令和 SQL 是一类东西" | 元命令归 `psql` 管，SQL 归服务器管，**报错外形不同** |

### 为什么三类错误报错不同

```
你 → psql.exe（客户端） → 网络 → postgres.exe（服务器）
      ↑ 这一步能失败              ↑ 这一步也能失败
```

| 实验 | 报错里出现 | 到服务器了吗 | 问题在 |
|---|---|---|---|
| A（停机） | `Connection refused` | ❌ **没到** | 服务没启动 |
| B（主机错） | `Connection refused` | ❌ **没到** | 地址不对 |
| C（端口错） | `Connection refused` | ❌ **没到** | 端口不对 |
| D（元命令错） | `invalid command \dtx` | ❌ **没发出去** | `psql` 自己的命令拼错了 |

**看外形：**

| 谁在报错 | 外形 | 例子 |
|---|---|---|
| `psql`（客户端） | 一行，`psql: 错误: ...` | `invalid command \dtx` |
| PostgreSQL（服务器） | 带 `致命错误` / `ERROR`，内容具体 | `角色"..."不存在` |

### 还有一条：没有报错的那种"错误"

**在 `psql` 里敲一条 SQL 但忘掉分号：**

```sql
SELECT version()
```

**屏幕上没有输出，提示符变成：**

```
postgres-#
```

**注意 `=` 变成了 `-`。**

> **`psql` 在用提示符告诉你："你这条语句还没结束，我还在等你继续。"**
> 因为 SQL 以 `;` 结尾。没有 `;`，它就认为你没写完。

**以后常见**：长 SQL 忘了分号、引号少一半、括号没闭合，都会卡在 `-#`。
**看到 `-#` 不要等** —— 不是数据库卡了，是语句不完整。补 `;` 或敲 `\r`。

## 四、解释原理

### （一）它怎么工作

**`psql` 有两种用法：**

| 用法 | 命令形态 | 特点 |
|---|---|---|
| 执行一条就走 | 带 `-c` | 适合脚本、验证 |
| 交互界面 | **不带 `-c`** | 连着敲，适合探索 |

**提示符 `postgres=#` 分三部分：**

| 部分 | 含义 |
|---|---|
| `postgres` | 当前连接的**数据库名称** |
| `=` | `psql` 提示符的一部分 |
| `#` | 当前用户**通常具有超级用户权限** |

> ⚠️ **不要记成"`=` 永远代表普通用户"。**
> 普通用户的提示符常见形式是 `=>`，但**别靠猜提示符判断身份** ——
> 可靠的做法是敲 `\conninfo`。

**元命令和 SQL 的区别，记死：**

| | 开头 | 结尾 | 谁处理 | 错了谁报 |
|---|---|---|---|---|
| **元命令** | `\` | **不带分号** | `psql` | `psql` |
| **SQL** | 关键字 | **必须带 `;`** | 服务器 | 服务器 |

**每条命令讲三层：**

| 命令 | 谁处理 | 出错时谁报错 | 怎么反推 |
|---|---|---|---|
| `\l` `\dt` `\d` `\c` | `psql` | `psql`（`invalid command`） | 命令没发出去，是拼写问题 |
| `SELECT ...` | 服务器 | 服务器（`ERROR: ...`） | 语句发到了，是 SQL 或对象名问题 |
| `psql` 连接本身 | `psql` 发起 | 两边都可能 | `Connection refused` = 客户端；`FATAL` = 服务器 |

### （二）为什么这样设计

```
存在的问题
  每次只执行一条 SQL，中间要反复重连，没法"边看边改"
        ↓
为什么旧的做法不够用
  · 想查"有哪些库"，得写一条又长又难记的系统表 SQL
  · 想连续敲十条，要连十次
        ↓
这个设计解决了什么
  · 交互界面：连一次，反复敲
  · 元命令：把常用的"看结构"动作做成两个字符
        ↓
它带来了什么新代价
  · 元命令只在 psql 里有 —— 换客户端（DBeaver、pgAdmin）就不认
  · 元命令的输出给人看，不便于程序读（程序要用 -tAc）
  · 多了一层"谁在处理"的复杂度 —— 但也正是这一层让报错可辨认
```

### （三）好处和代价

| 用元命令，好处是什么 | 代价是什么 |
|---|---|
| 短，不用背系统表 | 只在 `psql` 里有，不通用 |
| 自动格式化，列对齐 | 输出不能直接喂给程序 |
| 查库、切库、看结构一步到位 | 它不是 SQL，学不到"数据库怎么描述自己" |

**什么条件下该换别的做法：**

- 要**写进程序** → 用 SQL 查系统表，或 `-tAc`
- 要**跨数据库软件通用** → 也得用 SQL
- **自己探索、排查、调试** → 元命令最顺手

## 五、提炼判断规律

**判断规则（要有顺序）：**

```
看到报错
  ↓
第一步：有没有 Connection refused / timeout？
        有 → 还没到服务器 → 查服务开没开、-h、-p
  ↓
第二步：有没有 FATAL / 致命错误 / ERROR？
        有 → 已经到服务器 → 查用户、数据库、SQL
  ↓
第三步：有没有 invalid command？
        有 → 客户端处理失败，命令没发出去 → 查命令拼写，敲 \?
  ↓
第四步：没有任何报错，但提示符变成 -#？
        → 语句没写完 → 补 ; 或敲 \r
```

**支撑它的对照表：**

| 现象 | 谁报的 | 到服务器了吗 | 先查什么 |
|---|---|---|---|
| `Connection refused` / `10061` | `psql` | ❌ 没到 | 服务、`-h`、`-p` |
| `timeout` / 卡住很久 | `psql` | ❌ 没到 | `-h`（地址不可达） |
| `invalid command \xxx` | `psql` | ❌ 没发 | 元命令拼写，`\?` |
| 提示符变 `-#` | 谁都没报 | ❌ 没发 | 补 `;` 或 `\r` |
| `致命错误: 角色"..."不存在` | 服务器 | ✅ 到了 | `-U` |
| `致命错误: 数据库"..."不存在` | 服务器 | ✅ 到了 | `-d` |
| `ERROR: 关系"..."不存在` | 服务器 | ✅ 到了 | 表名 / 选对库了吗 |

**边界：** 这套判断在**认证阶段**会变复杂 —— 比如"用户不存在"和"密码错"可能报成同一类。
那时以报错里的 `DETAIL`/`HINT` 为准。

**一条通用技巧：**

> 报错里出现了**只有服务器才知道的东西**（有哪些用户、哪些库、哪些表）——
> 说明服务器活着，而且你已经连上它了。
> 报错里只有网络词（refused、timeout），说明你还没摸到服务器。
