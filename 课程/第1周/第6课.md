# 第 6 课：把整个环境重建一遍

> **本课对应**：`README.md` 第 1 周 Day 6（第 1 周收尾）
> **前置**：`课程/第1周/第1课.md` ~ `第5课.md`
> **状态**：✅ 已完成（收尾时发现脚本一个真 bug，已定位并给出修法）
> **读完本课能做出什么**：删掉整个数据库，用**一个脚本**从零重建出来
> **本课产出的长期文件**：**`init_db.sql`** ← 第 1 周唯一进 git 的产出物

**本课的点**

- **重点**：写一个**可重复执行**的建库脚本
- **难点**：脚本里的**顺序依赖** —— 角色 → 库 → 表，不能乱
- **普通点**：`psql -f` 跑脚本、`\c` 在脚本里切库、`\gexec`

> **⚠️ 路径不要照抄本文** —— 两台机器盘符不同（公司 `G:` / 家里 `C:`）。
> 去 `速查/PostgreSQL速查.md` 的 A 段抄对应那块。

**今天唯一要形成的模型：**

> **一个数据库环境，应该能用一个脚本从零重建出来。
> 因为"能重建"意味着：你随时敢删、随时能重来，不怕搞坏。
> 可重复执行靠的不是逐条判断"存不存在"，而是开头先把旧的拆干净。**

## 一、今天解决什么问题

**你有没有过这种担心：万一我把数据库搞坏了，能不能回到原样？**

学到这里，手上有一堆"散装操作"：
Day 3 建了角色和库，Day 4 知道了数据目录，Day 5 学会了跑脚本 ——
**但这些都是一条条手敲的。手敲的东西，重来一次就会漏、会写错。**

**真正的分界线：**

> 手敲过的操作，是"你会了"。
> **能写成一个别人（和未来的你）照着跑就行的脚本，才叫"你掌控了"。**

**今天学的就是这个 —— 它叫初始化脚本（`init` script）。**

**一句话说：把 Day 1–5 干的那些事写进一个 `.sql`；然后故意把库删掉，用它重建一次。**

**你可能原来是这样理解的：**

> 脚本就是把命令抄到一个文件里，方便一次跑完。

**这个理解不够 —— 关键是那个词：**

> **可重复执行（idempotent）：不管现在是什么状态，跑完都得到同一个结果。**

**这个理解错在哪？** `CREATE ROLE` 和 `CREATE DATABASE` **跑第二次会直接失败**。
"抄命令"的脚本只能跑一次 —— **那不叫可重复。**

**学完你能做出什么：** 把 `learn_sql` 和 `learn_user` 全删了，
然后一条命令重建回来，里面有表、有索引、有数据。

## 二、动手实验

### 0. 先检查环境

```powershell
$PG   = "G:\Project\PostgreSQL_pocket\pgsql\bin"
$DATA = "G:\Project\PostgreSQL_pocket\pgdata"
$LOG  = "G:\Project\PostgreSQL_pocket\pgdata\server.log"

# 先确认服务开着
& "$PG\pg_ctl.exe" -D $DATA status

# 如果没开，跑这一条 = 把服务打开
& "$PG\pg_ctl.exe" -D $DATA -l $LOG start
```

| `status` 打印 | 下一步 |
|---|---|
| "正在运行"、退出码 0 | 跳过 `start`，直接往下 |
| "没有服务器进程"、退出码 3 | **跑上面第二条 `start`** |

**先看现状**（这就是你一会儿要重建的东西）：

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "\l"
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "\du"
```

### 1. 今天的最小工具箱

| 命令 | 干什么 | 谁处理 |
|---|---|---|
| `psql -f 文件` | **从外面**执行整个脚本，跑完退出 | `psql` |
| `\i 文件` | **在 psql 里**执行脚本，跑完不退出 | `psql` |
| `DROP DATABASE IF EXISTS 库名` | 有就删，没有就算了 | 服务器 |
| `DROP ROLE IF EXISTS 角色` | 同上 | 服务器 |
| `\gexec` | 把上一条查询的**结果当 SQL 再执行** | `psql` |
| `\c 库名` | 在脚本里切库 | `psql` |
| `CREATE TABLE IF NOT EXISTS` | 有就不建，没有才建 | 服务器 |

### 2. 实验 A：先手敲一遍，看看会发生什么

**先进 `psql`，故意在库里面建同名库：**

```sql
CREATE DATABASE learn_sql;
```

**预计输出：**

```
ERROR:  database "learn_sql" already exists
```

**现在带上 `DROP` 再试：**

```sql
DROP DATABASE IF EXISTS learn_sql;
CREATE DATABASE learn_sql OWNER learn_user;
```

**第一次成功。原样再跑一遍 —— 也成功。**

**这就是"可重复"和"不可重复"的差别。**

### 3. 实验 B / C / D：三个错误，各有目的

| 实验 | 错误类型 | 它想打破的理解 |
|---|---|---|
| B | 环境错误（在错的库里跑建库语句） | "脚本跑不了是脚本写错了" |
| C | 用户错误（语句没写完就敲元命令） | "元命令和 SQL 可以随便混" |
| D | **参数错误（先删角色后删库）** | "删除顺序无所谓" |

**B —— 在 `learn_sql` 里面建 `learn_sql`：**

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -d learn_sql -c "CREATE DATABASE learn_sql;"
```

**C —— 语句没写完就敲元命令**（在 `psql` 里）：

```sql
SELECT 1
\c postgres
```

**D —— 故意先删角色：**

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "DROP ROLE learn_user;"
```

**这一条会失败** —— 而且它正是"顺序依赖"最硬的证据。见第三节。

## 三、观察现象和解释

### 先自己想一下：为什么脚本必须"可重复执行"？

**因为它真正的用途是"重建"，不是"初始化一次"。**

**任何一次意外（改坏了、删错了、换机器了），你想要的都是"恢复到干净状态"。**
脚本只能跑一次，你就得先手动清理再跑 —— 价值少了一半。

**可重复执行的两个障碍：**

| 障碍 | 报错 | 怎么绕 |
|---|---|---|
| 对象已存在 | `database "learn_sql" already exists` | 先 `DROP ... IF EXISTS` |
| 对象不存在却想删 | `database "learn_sql" does not exist` | 用 `IF EXISTS` 让它别报错 |

**`IF EXISTS` 和 `IF NOT EXISTS` 是一对兄弟。**

### 常见误解 → 更正

| 大多数人会以为 | 其实是 |
|---|---|
| "脚本 = 把命令抄进文件" | **脚本 = 不管当前什么状态，跑完结果都一样** |
| "`CREATE DATABASE` 跑两次没关系" | **会报错。** 必须先 `DROP DATABASE IF EXISTS` |
| "`CREATE ROLE` 也有 `IF NOT EXISTS`" | **没有。** `CREATE DATABASE` 也没有 —— 只能靠 `DROP` 兜 |
| "顺序无所谓，反正都在一个文件里" | **顺序是硬依赖**：角色 → 库 → 表 |
| "先删角色还是先删库都行" | **必须先删库、再删角色** —— 库的 owner 是那个角色 |
| "在库里面也能建别的库" | **不能。** `CREATE DATABASE` 是服务器级动作（Day 3 学的） |
| "建库时可以随便指定 owner" | **不能。** 那个角色必须**已经存在** |
| "`IF NOT EXISTS` 是脚本可重复的关键" | **不是。** 真正起作用的是开头的 `DROP` |

### `\gexec` 是干什么的

**它是"条件执行"的朴素实现。**

```sql
-- 查：learn_user 存在吗？不存在才生成"建角色"这句话
SELECT 'CREATE ROLE learn_user LOGIN PASSWORD ''learn_pass'''
 WHERE NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'learn_user');

-- 把上一条查询的结果当成 SQL 执行
\gexec
```

**读法**：`WHERE` 不成立 → 返回**零行** → `\gexec` 拿到零行就**什么都不做**。

**这是另一种"可重复"的写法**：不删旧的，只在缺失时补。
**它和"先删后建"的区别见四（三）。**

### `DROP ROLE` 的顺序问题（本课最硬的一条）

**为什么必须先删库？**

```
learn_sql 的 owner 是 learn_user
        ↓
先删 learn_user → 服务器拒绝："还有对象依赖我"
        ↓
所以要先删 learn_sql，把依赖解掉，再删 learn_user
```

**这不是"约定"，是服务器的强制检查。** 顺序反了**一定**失败。

## 四、动手：写 `init_db.sql`

### 文件放哪

```
G:\Project\my_PostgreSQL_project\init_db.sql
```

> 这个文件**在项目文件夹里** —— 因为它**要进 git**。
> 数据目录和程序在 `PostgreSQL_pocket`（项目外），**这个在项目里**。别放混。

### 完整的脚本

```sql
-- =============================================================
-- init_db.sql —— 重建学习用的数据库环境
--
-- 可重复执行：不管现在什么状态，跑完都得到同一个结果。
-- 靠什么做到：开头的 DROP ... IF EXISTS 把旧的拆干净，后面全在空环境上建。
-- （所以 CREATE TABLE 的 IF NOT EXISTS 只是保险，真正起作用的是开头的 DROP）
--
-- 怎么跑（必须用超管，因为要建角色和库）：
--   从外面跑：psql -U postgres -h 127.0.0.1 -f init_db.sql
--   进了 psql 再跑：\i init_db.sql    （跑完会停在 learn_sql 里）
-- =============================================================

-- 第 1 段：把旧的全部拆掉（顺序不能反！）
-- DROP DATABASE 必须在"没有别人连着它"时才能成功
DROP DATABASE IF EXISTS learn_sql;

-- 角色也要拆。注意顺序：库的 owner 是 learn_user，
-- 所以必须先删库、再删角色 —— 反了会被拒绝（还有对象依赖它）
DROP ROLE IF EXISTS learn_user;

-- 第 2 段：建角色
-- 注意：CREATE ROLE 没有 IF NOT EXISTS，所以"可重复"靠的是上面那句 DROP
CREATE ROLE learn_user LOGIN PASSWORD 'learn_pass';

-- 第 3 段：建库
-- OWNER 指定的角色必须已经存在 —— 这就是第 2 段必须在第 3 段前面
CREATE DATABASE learn_sql OWNER learn_user;

-- 第 4 段：切到新库里
-- \c 是 psql 的元命令，不带分号
\c learn_sql

-- 第 5 段：建表
-- 注意：下面这些都发生在 learn_sql 库里了
-- IF NOT EXISTS 在这里其实是"多余保险"：前面 DROP 过整个库，表必然不存在。
-- 留着它是为了"万一你单独把这段拎出来跑"时不炸。
CREATE TABLE IF NOT EXISTS notes (
    -- id = 每条笔记的唯一编号
    -- BIGSERIAL = 自动往上加的大整数
    id BIGSERIAL PRIMARY KEY,

    -- title = 标题，不能留空
    title TEXT NOT NULL,

    -- body = 正文，可以很长
    body TEXT,

    -- created_at = 创建时间，带时区（Day 7 细讲为什么必须带）
    -- DEFAULT now() = 我不填的话，自动填"现在这个时刻"
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 看一眼：表建好了，但里面是空的（这是正常的中间状态）
\dt
SELECT count(*) AS 行数 FROM notes;

-- 第 6 段：建索引
-- 让"按标题搜"变快；IF NOT EXISTS 检查的是"索引名"在不在
CREATE INDEX IF NOT EXISTS notes_title_idx ON notes (title);

-- 第 7 段：塞两条示例数据
-- 注意：这两行不是"存活的"，是每次跑脚本时"重新插入"的 —— 库被整个删过
INSERT INTO notes (title, body) VALUES
    ('第一条笔记', '这是重建脚本塞进来的'),
    ('第二条笔记', '每次跑脚本，这两行都是重新插入的');

-- 第 8 段：自检
\dt

-- 四列都看：body 有值，created_at 是自动填的（INSERT 里没给它）
SELECT * FROM notes ORDER BY id;

-- 再看一眼结构：\d 告诉你这张表"允许"存什么
\d notes
```

### 关键点解释

| 段 | 为什么这么写 |
|---|---|
| 1 | **先删库、再删角色** —— 顺序反了会被"对象依赖"拒绝 |
| 2 | `CREATE ROLE` **没有** `IF NOT EXISTS`，可重复靠第 1 段的 DROP |
| 3 | `OWNER learn_user` —— 让库归你那个普通账号；**角色必须已存在** |
| 4 | `\c` **不带分号**，由 `psql` 处理（Day 2 学的） |
| 5 | 建表 + **中间自检**（让你看见"表存在、0 行"这个状态） |
| 6 | `IF NOT EXISTS` 检查的是**索引名** |
| 7 | `INSERT` 没有存在性判断 —— **靠第 1 段保证不重复插入** |
| 8 | 末段自检 —— **脚本自己告诉你成没成功** |

**怎么跑**

**第一步：服务必须是开着的。** 回上面的「0. 先检查环境」——
那里 `status` 和 `start` 是连在一起的，照那个来。

**方式一：从外面跑（跑完退出）**

```powershell
# 跑脚本
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -f "G:\Project\my_PostgreSQL_project\init_db.sql"
```

| 参数 | 作用 |
|---|---|
| `-f 文件路径` | 执行文件里的所有内容 |
| `-U postgres` | **必须用超管**，因为要建角色和库 |
| 没写 `-d` | 默认连 `postgres` 库 —— **这是对的**，建库要在别的库里做 |

**方式二：进 `psql` 再跑（跑完不退出，且停在 `learn_sql` 里）**

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1
```

```sql
\i G:/Project/my_PostgreSQL_project/init_db.sql
```

> ⚠️ `\i` 的路径用**正斜杠**或引号包起来，反斜杠在 `psql` 里是转义字符。

### 这里应该出现一个让我"咦"的现象

**原样再跑一遍。**

**它会失败** —— 在 `CREATE ROLE learn_user` 那一行：

```
ERROR:  role "learn_user" already exists
```

**而且更糟：此时库已经被删了、新库还没建起来。**

**为什么？** 因为第 1 段只删了**库**，没删**角色**。角色活过了第一遍。

**这就是"看起来可重复"和"真的可重复"的差别。** 这正是本课的价值所在。

## 五、提炼判断规律

**判断规则（要有顺序）：**

```
脚本跑失败了
  ↓
第一步：是不是 Connection refused？
        是 → **服务没开，脚本一个字都没跑** → 回 Day 2 那套判断
  ↓
第二步：是不是"对象已存在"？（already exists）
        → 缺 DROP ... IF EXISTS
  ↓
第三步：是不是"对象不存在"？（does not exist）
        → 缺 CREATE，或者顺序错了（用到了还没建的东西）
  ↓
第四步：是不是"还有对象依赖它"？（cannot be dropped because ...）
        → **删除顺序反了**：先删被依赖的（库），再删依赖者（角色）
  ↓
第五步：是不是"权限不够"？（permission denied）
        → 当前角色没有这个权限（建库要 CREATEDB 或超管）
  ↓
第六步：以上都不是 → 看**第一条** ERROR
        脚本是自上而下跑的，**第一个错误才是根因**，后面多半是连带的
```

**支撑它的对照表：**

| 报错 | 真正原因 | 改哪里 |
|---|---|---|
| `database "X" already exists` | 没先删 | 加 `DROP DATABASE IF EXISTS X;` |
| `role "Y" already exists` | **没删角色** | 加 `DROP ROLE IF EXISTS Y;` |
| `role "Y" cannot be dropped because some objects depend on it` | **删除顺序反了** | 先删库，再删角色 |
| `database "X" does not exist` | 没先建 / 顺序错 | 检查 CREATE 在不在前面 |
| `role "Y" does not exist` | owner 用了还没建的角色 | 把建角色挪到建库前面 |
| `cannot drop the currently open database` | 正连着要删的库 | 换个库连 |
| `permission denied to create database` | 当前角色没有 `CREATEDB` | 用超管跑 |

**边界：** 这套判断**只适用于"脚本本身的问题"**。
第一条 ERROR 若是 `Connection refused`，**那根本不是脚本的问题** —— 服务都没开。

**一条最有用的经验：**

> **脚本自上而下执行。看第一行报错就够了 ——
> 后面那一串往往是"因为前面失败了"连带的。**

### 总结、回顾

**今天学了什么：**

把 Day 1–5 学的串起来，写成一个可重复执行的脚本。
核心两件事：**拆旧必须在建新之前**（`DROP ... IF EXISTS`），
以及**顺序是硬依赖**（先删库再删角色；角色 → 库 → 表）。
还撞到一个真 bug：`CREATE ROLE` 没有 `IF NOT EXISTS`，**只删库不删角色，脚本就跑不了第二遍**。

**和前面什么关系：**

Day 3 教你**手敲**建角色建库；今天把它们**变成文件**。
Day 5 教你 `\i` 跑脚本；今天**真的写了一个值得跑的脚本**。
这是第 1 周的收口：从"会敲命令"变成"有一份能重复使用的东西"。

### 心智模型

> **一个数据库环境 = 一个数据目录 + 一份能重建它的脚本。
> 脚本从上往下跑，每一步都依赖前面已建好的东西：角色 → 库 → 表。
> 要让它可重复，就得先拆干净再重建 —— 所以 `DROP ... IF EXISTS` 永远在最前面，
> 而且**删除顺序是依赖的反序**：先删被依赖的（库），再删依赖者（角色）。**

| `\c` 后面为什么不写分号？ | 它是 `psql` 的元命令，不是 SQL | 四 |
| 脚本第二遍跑，数据会变 4 行吗？ | **不会，还是 2 行** —— 库被整个删了重建 | 四 |
| 为什么 `notes` 表用 `IF NOT EXISTS` 但 `INSERT` 不用？ | 表是结构；数据靠**最前面的 DROP** 保证不重复 | 四 |
| 那 `IF NOT EXISTS` 在这里有用吗？ | **基本是多余保险** —— 前面 DROP 过整个库，真正起作用的是 DROP | 三、四 |
| 在 `learn_sql` 里面能建 `learn_sql` 吗？ | **不能。** 建库是服务器级动作 | 二（2） |
| `SELECT id, title FROM notes` 为什么没有 `body`？ | **因为只点了两列。** 想看全部用 `SELECT *` | 四 |
| `\d notes` 和 `SELECT * FROM notes` 有什么区别？ | `\d` 说"允许存什么"（结构）；`SELECT *` 说"现在存了什么"（数据） | 四 |
| 脚本报了一串错，看哪个？ | **只看第一条 ERROR** | 五 |
| `-f` 和 `\i` 有什么区别？ | `-f` 从外面跑完退出；`\i` 在 `psql` 里跑完不退出 | 四 |
| `init_db.sql` 为什么放在项目文件夹里？ | 因为**它要进 git**；数据目录和程序在项目外 | 四 |
