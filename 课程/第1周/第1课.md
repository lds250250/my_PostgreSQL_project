## 一、为什么学

**你有没有遇到过这种情况：想删掉数据库重来一遍，却发现你根本不知道它把数据存在哪、怎么让它停下来？**

用 Installer 装的数据库就是这样 —— 它变成一个"服务"，开机自己起来，你只能点图形界面。

但我们后面要做的事，全是"折腾数据库"：

- 第 9 周要造 100 万行，测完可能想删库重来
- 第 10 周要专门制造一次"不可重复读"
- 第 11 周要**故意制造一次死锁**

这些都要你**随时能启动它、停掉它、删掉它重来**。

**今天学的就是这个 —— 它叫 PostgreSQL，我们走免安装（ZIP）这条路把它跑起来。**

**一句话说：数据库其实只是"一个文件夹 + 一个正在运行的进程"。今天就是把这两样亲手做出来，让你完全掌控它。**

**学完你能做出什么：** 一条命令启动数据库、一条命令停掉它，并且 `SELECT version();` 打印出 `PostgreSQL 18.x`。

## 二、好处和代价

先摆三条路的取舍。今天选 ZIP：

| 用了 ZIP 版，好处是什么 | 用了 ZIP 版，代价是什么 |
| --- | --- |
| 不需要管理员权限，解压就能用 | **每次开机要手动启动**，它不会自己起来 |
| 删掉就是删掉，恢复就是恢复 | 没有图形界面，全部靠命令行 |
| 想换版本就换个文件夹，可以并存 | **没有自动安全更新**，要自己关注新版本 |
| 你能亲眼看见"数据目录"和"进程" | 第一次要记住 `initdb` / `pg_ctl` 两条命令 |

**另外两条路各自什么时候用：**

| 方案 | 什么时候选 |
| --- | --- |
| **Docker** | 第 15 周正式学。它能"秒级建库、删卷即回滚"，是最适合做实验的方式 |
| **Installer** | 只是想要个能用的数据库、不想碰命令行时 |

**什么条件下该换别的做法：** 等你开始"一天要建三次库、删三次库"做实验时（第 9 周起），ZIP 版会开始烦 —— 那正是第 15 周上 Docker 的理由。现在不急。

## 三、代码段

### 零、每节课的开场：定一个变量

**这一段的作用：后面 120 天你每天都要敲 `psql` / `pg_ctl`。每次写完整路径，手会先废掉。**

所以**每节课开头，先敲这一行**（变量只对当前窗口有效，新开窗口要重来一次）：

```powershell
# 声明 $PG 代表"PostgreSQL 的可执行程序在哪个文件夹"
$PG = "G:\Project\PostgreSQL_pocket\pgsql\bin"

# 确认变量生效 —— 应该原样打印出上面那个路径
$PG
```

**之后本课所有完整路径，你都可以简写：**

| 完整写法 | 简写 |
| --- | --- |
| `& "G:\Project\PostgreSQL_pocket\pgsql\bin\psql.exe"` | `& "$PG\psql.exe"` |
| `& "G:\Project\PostgreSQL_pocket\pgsql\bin\pg_ctl.exe"` | `& "$PG\pg_ctl.exe"` |

### 一、下载和解压（今天已完成）

**这一段的作用：把 PostgreSQL 的"程序"拿到本地。**

去这个页面下载（选 **Windows x86-64**、版本 **18.x** 的 binaries，是 .zip 不是 .exe）：

```
https://www.enterprisedb.com/download-postgresql-binaries
```

> 这个页面是 PostgreSQL 官方下载页 `postgresql.org/download/windows` 指向的免安装二进制来源，和官方 Installer 同源。

**今天你已经解压到 `G:\Project\PostgreSQL_pocket\pgsql`，目录长这样：**

```
G:\Project\PostgreSQL_pocket\
├── pgsql\
│   ├── bin\        <- 所有可执行程序，psql.exe 就在这里
│   ├── lib\        <- 依赖库
│   ├── share\      <- 配置文件模板、时区数据
│   └── include\    <- 头文件（第 16 周编译 pgvector 才会用到）
└── pgdata\         <- 数据目录，由第二节的 initdb 创建
```

> **注意**：程序和数据放在**项目文件夹外面**（`G:\Project\PostgreSQL_pocket\`），学习笔记放在项目里（`G:\Project\my_PostgreSQL_project\`）。
> **这样分开放是对的** —— 数据库是个独立的东西，几百 MB，不该和你的笔记混在一起。

**解压出来的 `pgsql\` 不要提交进 git**，每台机器自己装一份。

### 二、建数据目录（今天已完成）

**这一段的作用：把一片空文件夹，变成"一个能用的数据库"。**

```powershell
# 调用 initdb.exe，在一片空目录里初始化出一个数据库。
$PG = "G:\Project\PostgreSQL_pocket\pgsql\bin"

& "$PG\initdb.exe" `
  -D "G:\Project\PostgreSQL_pocket\pgdata" `
  -U postgres `
  -E UTF8 `
  --locale=C
```

**逐行说明（PowerShell 里反引号 `` ` `` 表示"这一行还没完，下一行接着"）：**

| 这一行 | 干什么 |
| --- | --- |
| `& "$PG\initdb.exe"` | 运行初始化程序。`&` 是 PowerShell 调用带引号路径的写法 |
| `-D "G:\...\pgdata"` | **D**ata directory：数据放哪。这个文件夹会被创建出来 |
| `-U postgres` | 超级**U**ser 叫什么。这里指定为 `postgres` |
| `-E UTF8` | **E**ncoding：编码用 UTF-8 |
| `--locale=C` | 排序规则用最原始的 `C` |

**代码块外面的补充：**

- **为什么数据目录要和程序分开放**：数据是你的，程序是工具。哪天想换 PostgreSQL 版本，只换 `pgsql\`，`pgdata\` 不动。
- **为什么路径尽量别带空格和中文**：命令行里要给它加引号，多一层容易出错。纯 ASCII 路径能省掉一半的报错。
- **`--locale=C` 是什么，为什么不用默认**：默认跟随 Windows 语言环境，排序结果跟教程对不上。`C` 是最原始、最可预测的排序。
- **常见的坑**：`-D` 指向的文件夹**必须是空的**。已经有东西的话，`initdb` 会拒绝执行。

### 三、启动服务（今天已完成）

**这一段的作用：把数据库"跑起来"。数据目录是死的，进程是活的。**

```powershell
# 启动数据库进程。
# -D 告诉它用哪个数据目录，-l 让它把运行日志写进文件。

& "$PG\pg_ctl.exe" `
  -D "G:\Project\PostgreSQL_pocket\pgdata" `
  -l "G:\Project\PostgreSQL_pocket\pgdata\server.log" `
  start
```

| 这一行 | 干什么 |
| --- | --- |
| `...\pg_ctl.exe` | **pg** 的 **ctl**（control）：启动 / 停止 / 重启数据库 |
| `-D "..."` | 和上面一样，用哪个数据目录 |
| `-l "..."` | **l**og：日志写到哪个文件 |
| `start` | 动作是"启动" |

**记一下这几个动作，它们是一套：**

| 想干什么 | 命令最后那个词换成 |
| --- | --- |
| 启动 | `start` |
| 停止 | `stop` |
| 重启 | `restart` |
| 看状态 | `status` |

**注意：启动完不代表完事，得确认真的起来了 —— 下一步就是干这个的。**

### 三点五、确认它真的起来了

**这一段的作用：刚启动完，"没报错"不等于"能连上"。要分两步验。**

**第一步，问进程：**

```powershell
# 0 = 正在运行    3 = 没有运行
& "$PG\pg_ctl.exe" -D "G:\Project\PostgreSQL_pocket\pgdata" status

# 看它刚才那个退出码是多少
$LASTEXITCODE
```

**第二步，真连一次才算数：**

```powershell
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "SELECT version();"
```

**为什么要分两步 —— 这是本课第一个反直觉的地方：**

> ⚠️ `pg_ctl status` 判的是**进程在不在**；`psql` 试的是**能不能连上**。这两件事不是一回事。
> 进程可以活着，但端口配错了、监听地址不对、`pg_hba.conf` 不让连 —— 这时候 `status` 说"在运行"，`psql` 却连不上。
> **所以判断"能不能用"，永远以 `psql` 实测为准。**

### 四、连上去

**这一段的作用：用一个客户端程序，连进正在运行的数据库。**

```powershell
# 连接数据库，并执行一条 SQL 看版本。
# -U 用哪个用户，-h 连哪台机器，-c 执行这条 SQL 然后退出。

& "$PG\psql.exe" `
  -U postgres `
  -h 127.0.0.1 `
  -c "SELECT version();"
```

| 参数 | 全称 | 干什么 |
| --- | --- | --- |
| `-U` | **U**ser | 用哪个用户连 |
| `-h` | **H**ost | 连哪台机器。写 `127.0.0.1` 就是本机 |
| `-d` | **D**atabase | 连哪个库。今天不用写，默认连到 `postgres` 库 |
| `-p` | **P**ort | 端口。今天不用写，默认 `5432` |
| `-c` | **c**ommand | 执行这条 SQL 然后退出 |

**学完你能做出什么：** 屏幕上打印出 `PostgreSQL 18.x`，说明整条链路通了。

## 四、跑一下、debug、看效果

### 1. 怎么跑

**在你自己电脑的 PowerShell 里**，按顺序敲上面三段代码：下载解压 → `initdb` → `pg_ctl start` → `psql`。

**注意：`initdb` 和 `pg_ctl` 的输出会打回终端；`pg_ctl start` 结束时不报错就是成功了。**

### 2. 应该看到

**`initdb` 成功时，最后几行长这样：**

```
initdb: warning: enabling "trust" authentication for local connections
You can change this by editing pg_hba.conf or using the option -A, or
--auth-local and --auth-host, the next time you run initdb.
Success. You can now start the database server using:

    pg_ctl -D "G:\Project\PostgreSQL_pocket\pgdata" -l logfile start
```

**那句 `warning` 不是错误**，先不用管它（第 3 周会讲 `pg_hba.conf` 时解释它）。

**`pg_ctl start` 成功时会打印：**

```
waiting for server to start.... done
server started
```

**`psql` 成功时（你刚才看到的，`(1 行记录)` 是中文环境下的 `(1 row)`）：**

```
                                                 version
----------------------------------------------------------------------------------------------------------
 PostgreSQL 18.6 on x86_64-windows, compiled by msvc-19.44.35228, 64-bit
(1 行记录)
```

**看到什么算不对：**

| 屏幕上出现 | 说明什么 |
| --- | --- |
| 版本号不是 `18.x` | 你机器上还有别的 PostgreSQL，`psql.exe` 用的是那一个 |
| 没有 `PostgreSQL` 字样 | 连上的不是 PostgreSQL（可能连到了别的数据库） |
| 报错 | 看下面第 3 步 |

### 3. 故意改坏一次

**先正常连上一次，把数据库关掉，再连一次。**

```powershell
# 第一步：把数据库停掉
& "$PG\pg_ctl.exe" -D "G:\Project\PostgreSQL_pocket\pgdata" stop

# 第二步：这时候再去连它
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -c "SELECT version();"
```

**你应该看到这样的报错（这是本课实际跑出来的原文，中文 Windows 上就是中文的）：**

```
psql: 错误: 连接到"127.0.0.1"上的服务器，端口5432失败：Connection refused (0x0000274D/10061)
        Is the server running on that host and accepting TCP/IP connections?
```

**怎么读这条报错 —— 从后往前读：**

| 报错里的句子 | 它在说什么 |
| --- | --- |
| `连接到"127.0.0.1"上的服务器，端口5432失败` | **这一句是结论**：连 `127.0.0.1` 的 `5432` 端口失败了 |
| `Connection refused (0x0000274D/10061)` | **这一句是真正的原因**：那个端口上没有程序在听。括号里是 Windows 的系统错误码 |
| `Is the server running...?` | 这是**提示**，不是原因。它只是在猜你可能忘了启动 |

**读报错的方法：先找结论那句，再找带具体原因的那句，最后才是问句（提示）。**

**还有一个信息藏在这条报错里**：它写的是 `端口5432`。你当时已经把配置改成 `5433` 了 —— 所以这条报错是在告诉你"**我按 5432 去连的**"，也就是说**配置文件还没生效**（因为服务当时是停的，没重新读配置）。

现在把它启动回来，再连一次，应该又能看到版本号。

### 4. 自己改一个地方

**把端口从 `5432` 改成 `5433`，看看会怎样。**

```powershell
# 先停掉
& "$PG\pg_ctl.exe" -D "G:\Project\PostgreSQL_pocket\pgdata" stop

# 用记事本打开配置文件
notepad "G:\Project\PostgreSQL_pocket\pgdata\postgresql.conf"
```

在记事本里按 `Ctrl+F` 搜 `port`，找到这一行：

```
#port = 5432
```

把前面的 `#` 去掉（`#` 表示"这一行被注释掉了，不生效"），把 `5432` 改成 `5433`，保存关闭：

```
port = 5433
```

```powershell
# 重新启动
& "$PG\pg_ctl.exe" -D "G:\Project\PostgreSQL_pocket\pgdata" start

# 用 5433 连 —— 应该成功
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -p 5433 -c "SELECT version();"

# 用 5432 连 —— 应该失败
& "$PG\psql.exe" -U postgres -h 127.0.0.1 -p 5432 -c "SELECT version();"
```

**看到 5433 成功、5432 失败，你就真的懂了 `-p` 和 `port` 配置的关系。**

**改端口这件事顺带教会我们两件事（比端口本身值钱）：**

| 学到什么 | 为什么 |
| --- | --- |
| **配置文件改了，必须重启才生效** | 数据库只在启动那一刻读一次配置文件。不重启，改了等于没改 |
| **客户端连哪个端口，由 `-p` 决定；服务端听哪个端口，由 `postgresql.conf` 决定** | 两个必须对上才能连上。这解释了为什么上面那条报错会写"端口5432" |

**第二条的推论**：你以后报"连不上"之前，先问自己两个问题 ——
**服务端在听哪个端口？我拿哪个端口去连的？**

**改完记得改回 `5432`**（把 `#` 加回去，或者把 `5433` 改回 `5432`），不然后面所有课的命令都要多带一个 `-p 5433`。

## 六、总结、回顾

**今天学了什么：**

PostgreSQL 不是"装上去的一个服务"，而是**一个数据目录加一个进程**。`initdb` 把空文件夹变成数据目录，`pg_ctl` 启停那个进程，`psql` 是连进去说话的工具。四条命令走通，你就能完全掌控它。

**和前面什么关系：**

`第0课` 把"仓库、生词本、两台机器"这些地基铺好了，但数据库还没影。今天补上最后一块 —— 现在你有能跑的数据库了，Day 2 开始就能讲怎么用它。
